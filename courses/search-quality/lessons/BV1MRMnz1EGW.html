微调数据怎么准备，才能让模型学到我们真正需要的能力？

来源：code秘密花园｜LLaMA Factory 微调教程：如何构建高质量数据集？ · 24 分 37 秒 · 深度阅读

假设一家企业想在内部部署一个能回答 Web 安全问题的模型。员工会拿业务代码来询问风险，也会问某种漏洞怎样预防。这些代码和需求文档可能涉及机密，不适合直接发到外部服务；企业又未必有资源部署非常大的模型。一个自然的想法是：选择较小的模型，再用 Web 安全领域的材料进行微调，让它在有限的范围里做得更好。

这里的案例选择 Qwen2.5-7B-Instruct 作为基础模型。目标包含两件事：回答安全知识问题，以及对业务场景和代码中的潜在风险作出分析。要达到这样的目标，光有一批“与安全有关的文字”还不够。模型需要接触具体的问题、合适的回答，以及我们希望它采用的分析方式。接下来准备数据的每一步，都要回到这个目标：这条材料究竟在教模型完成什么工作？

先看效果时，怎样理解“学会了”

可以先用几类问题观察微调前后的变化。第一类在训练材料里出现过，例如从防护角度解释静态分析恶意软件的原理。微调后回答更充分，说明模型可能学到了材料中的内容。但熟悉的题目做得好，还无法说明它遇到新问题也能做好，所以还要问训练材料中没有直接出现的领域问题。

第二类检查模型能否把知识组织起来，例如让它介绍 Web 安全的知识体系。我们希望看到漏洞、防护方法和相关概念之间有合理联系，不能只看它列了多少条。第三类把问题移到领域之外，例如询问化学知识体系，目的是观察专门训练安全知识以后，原先的其他能力是否还在。这三类问题分别关注记住材料、处理新问题和保留原有能力，不能互相替代。

回答更长、分析段落更多，也不能直接等同于推理更可靠。少量问答对比适合帮助我们发现变化；要判断泛化能力、是否过拟合，以及是否稳定超过更大的模型，还需要独立测试。过拟合可以先理解为过度熟悉训练样本，换一批真实问题就表现变差。保留这个区别，后面谈数据量和质量时才有清楚的判断对象。

一条训练数据，到底教模型做什么

这次任务采用 SFT，即监督微调。我们向模型提供输入与示范回答，训练它在类似输入下更容易生成符合要求的回答。一本安全书可以提供知识，但整本书直接放进去，与把知识组织成适合实际任务的问答，是两种不同的数据准备方式。如果部署后主要接受用户提问，训练样本就需要让模型接触这样的问答过程。

LLaMA Factory 支持的 Alpaca 格式，把一条样本的主要部分拆成 instruction、input 和 output。instruction 表达用户要求，input 放需要一同考虑的输入内容，output 是模型要学习的回答。还可以有 system，说明系统层面的要求，以及 history，保存此前的对话。ShareGPT 格式则按对话消息组织，能够表示不同角色的发言和工具交互。两种格式的核心作用都是把“谁给了什么信息，接下来应当怎样回应”表达清楚。

数据中的内容 在训练情境里意味着什么
用户要求与补充输入 模型需要理解的任务及条件
示例回答 希望模型学会生成的内容
系统提示词 回答需要遵守的整体要求
对话历史 当前问题之前已经发生的交流
工具调用及返回内容 某些对话任务中，模型怎样利用外部结果继续回答

真正操作时，还有一个容易混淆的地方：数据文件本身与“告诉程序怎样读取数据”的配置文件分开保存。dataset_info.json 为数据集登记名称、来源和字段对应关系。假如你自己的文件里，问题字段不叫 instruction，程序就需要知道哪一列对应问题、哪一列对应回答。这样，许多来源不同、字段名称不同的数据，才可以进入后续统一的处理流程。

数据进入训练前，还要经历一段转换。首先把不同结构整理成内部可处理的形式，再套用模型对应的对话模板，标明各轮消息的角色与边界；接着，分词器把文字转成模型处理的数字序列；最后，决定哪些位置参与训练损失的计算。损失衡量模型当前预测与目标内容之间的差距，训练据此更新参数。

对常见的助手回复训练，我们把用户要求作为条件，重点训练模型怎样接着回答。模型当然仍要利用用户输入，但“读取输入”和“把某段文字作为需要学着生成的目标”是不同的角色。因此，格式正确只解决了能否读入的问题，模板与标签设置还会决定实际训练了什么。具体字段和当前支持格式可对照 LLaMA Factory 数据准备文档，不要只靠文件扩展名判断数据已经准备好。

五种常见问题，为什么会让微调效果变差

先看数据太少。模型只见过少量固定问法，很容易熟悉这些样本，却没有接触足够多的条件变化。继续增加训练轮次，相当于反复学习同一小批材料，并不会自动补出缺少的场景。案例给出的经验是，面向 7B 模型的领域知识任务，可以从千条量级考虑准备数据；这个数字是经验起点，任务难度、基础模型原有能力和每条样本的信息量都会改变需求，不能当成统一的合格线。

接着是噪声。错别字、乱码、重复内容会降低材料质量，错误标注则会直接教给模型错误关系。例如情感分类任务里，一段明显的好评被标成差评，训练就会推动模型把这样的文本与差评标签联系起来。增加这种数据的数量，只会重复强化问题。因此，检查一条样本是否有效，应放在追求总条数之前。

第三种问题是样本分布与实际使用差得太远。假如训练评论中九成是正面评论，实际使用时正负评论却接近均衡，模型在训练中形成的倾向就可能不适合真实输入。这里要检查的对象是一整批数据的组成，即使每条标签单独看都正确，也可能因为某些类型出现得过多、另一些出现得过少，让最终表现失衡。

第四种问题很容易被“同一个领域”掩盖。想训练金融问答模型，就大量收集财经新闻，看起来方向一致。但新闻通常在叙述事件，用户问答要求围绕一个问题作解释。领域相关只说明材料在谈相近的事情，任务相关还要求材料展示我们希望模型完成的工作。准备 Web 安全数据时，也要区分介绍术语、分析场景和给出操作建议，不能把它们看作完全相同的训练目标。

最后是多样性不足。只有短句的样本，无法充分覆盖长问题和复杂条件；只有“解释某个概念”的指令，也很难覆盖需要推理和具体操作的任务。多样性包含问题的长度、表达方式、背景条件和要求完成的动作。把同一个问题换几个近义词，可能增加了表面数量，却没有增加多少新的情境。我们真正需要的是，让训练材料覆盖实际使用中会发生的差别。

把知识材料变成问答：先决定材料各自负责什么

这个案例的数据由几种来源共同构成。基础知识来自《白帽子讲 Web 安全》；较新的问题来自几篇相关论文，包括代码生成的安全风险、提示词注入与 Web Agent 安全，以及安全领域的人类认知偏差研究。书籍与论文承担的作用不同：前者帮助建立较完整的领域基础，后者补充具体的新问题。

此外，还由更强的教师模型生成一部分数据，补充材料覆盖不均的领域，并利用它输出的分析过程构造训练样本。这里的“蒸馏”可以理解为用强模型提供的示范训练较小模型。小模型能够学到什么，取决于示范是否正确、是否适合它的任务，以及训练后的实际表现；教师模型给出的答案同样需要检查，不能因为它更大就免于审核。

处理这些材料使用 Easy Dataset。整体顺序是：导入文献，提取可用文本，按结构分块，生成问题，生成回答，再审核与导出。不同模型可以分别负责长文本理解、回答生成和 PDF 视觉解析。这样的分工让我们看清每个模型被用在哪里，也有助于理解某类错误来自哪一步。例如，PDF 表格在解析时已经错位，后面问答生成再流畅，也可能只是在重复错误文本。

项目名称在这里还有实际作用：它会被用作后续蒸馏的顶级主题。因此，应写清楚准备训练的领域，避免使用与任务无关的临时名称。随后配置模型的服务地址、密钥和模型名称。对于涉及企业内部资料的任务，还需要分别看清这些生成环节会把资料发送到哪里；最终模型在本地部署，并不自动意味着准备数据的整个过程都在本地完成。

分块和提示词，怎样影响最后得到的问题

文献首先被转成便于处理的 Markdown 文本，再进行分块。一个文本块是模型生成问答时看到的一段材料。切得太碎，前后条件可能被拆开；切得过大，又可能把多个主题混在一起。案例采用按文本结构分块，块大小设为 2400，重叠长度为 150，并建议根据章节的实际长度调整。这些值服务于当前材料，不能脱离文献结构照搬。

问题生成密度也需要结合内容判断。案例配置为每 100 个字符生成一个问题，信息密集的材料可以生成得更密一些；重复铺垫较多的材料则未必有那么多独立问题。还设置一部分问题不带问号，因为真实用户并不总按标准书面疑问句提问。这种变化主要覆盖表达形式，不能代替问题本身的知识质量。

提示词用来明确生成任务的范围。材料里有英文论文，但目标数据是中文问答，因此先约定输出语言。然后约束问题聚焦 Web 安全，减少针对作者、引用文献等与目标任务无关的提问。回答则应直接回应问题，避免总以“根据提供的资料”开头。否则模型容易学会依赖一份在真实对话中并不存在的材料，或形成与用户问题无关的固定套话。

这些设置之后，仍要查看实际的领域分类和文本块。领域树把材料分到不同主题下，帮助观察哪些地方覆盖得多、哪些地方薄弱；文本块检查则关注一段材料是否完整，标题和正文是否配对，问题需要的条件是否被截断。只有这两层基本合理，批量生成问题才有可靠的起点。

增加多样性时，保持知识不变，改变解释对象和表达方式

这里采用了“类型与受众配对”的增强思路。类型指内容怎样呈现，例如学术说明、科普文章或故事；受众指内容面向谁，例如初学者、专业学生或需要教学材料的老师。把这两个维度结合，同一份知识就可以有不同的解释方式。

急救指南的例子比较直观。面向办公室工作人员时，需要强调怎样识别情况、接下来做什么，用词也要让没有医学训练的人看懂；面向医学生时，则可以增加专业术语和理论背景。两份内容的深度与组织方式不同，但涉及同一事实时仍应保持一致。增强的价值来自更丰富的表达与使用情境，不能通过随意改变事实来制造差异。

同样的思路用到训练数据上，可以帮助模型适应不同背景的提问者。不过，生成了多种版本还需要检查它们是否真正有区别，是否保留重要条件。如果五种版本只是替换了开头或语气，就很难带来预期的多样性；如果改写为了通俗而删掉了安全条件，反而会降低示范质量。因此，数据增强与审核应当一起考虑。

哪些问题应该删掉：几个具体例子

问题生成完成后，可以先检查它脱离文献能否成立。“这个变量里的 K 是什么”就有明显困难：用户没有给公式，模型不知道正在讨论哪一个 K。这样的问答依赖原来页面的上下文，如果训练样本里没有保留那段上下文，问题本身就是不完整的。

“作者在结论中提到哪些未来工作”则在询问某篇论文的写作内容。若目标是训练 Web 安全技术问答，这类问题与预期使用场景距离较远。“文献里的 Web 安全数据是什么”又过于笼统，没有说明要问数据类型、字段还是采集方式，回答容易同样笼统。它们需要删除或重写的理由不同：一个偏离任务，一个缺少明确对象。

案例还剔除了政策合规、实验硬件环境等问题。这要结合当时正在提取的数据主题理解：那一批样本希望聚焦数据构成、标注方式和样本特征，所以其他问题被排除。不能由此推成合规或实验环境一概没有训练价值；如果实际任务就要求回答这类问题，它们当然可以成为有价值的样本。

生成的问题 需要先判断的事情
“这个变量 K 是什么？” 必要公式和上下文是否包含在输入中
“作者未来要做什么？” 论文叙述是否属于目标任务
“Web 安全数据是什么？” 对象是否过于笼统，能否得到明确回答
关于合规政策或实验环境的问题 是否属于这一批数据要覆盖的主题

把问题先整理好，再批量生成答案，能减少一部分无效工作。随后还可以按领域标签让教师模型补充问答，改善不同主题的覆盖。标签数量均衡只是一个可观察的表面条件，我们仍要看每个主题下面的问题是不是有实质差别，以及这些问题是否贴近使用需求。

最后审核的，是完整问答能否成为好示范

到了数据管理阶段，应把问题与答案放在一起读。答案首先要与材料事实一致，没有关键错误，也没有把材料没有给出的结论补得过于确定。其次，它需要真正回应问题，避免堆入数据来源、模型训练效果等无关内容。回答越长，越需要逐项看它增加了哪些有效信息。

对知识边界和条件也要格外留意。涉及时间范围、数据格式、字段定义或标注标准时，缺掉其中一项可能改变整句话的意思；相同概念若用了多个容易混淆的名称，读者和模型都更难建立稳定关系。不同书籍、论文和蒸馏任务还可能产出重复问答，应检查是否有必要合并，而非把重复出现当成多份独立知识。

对于含糊的回答，需要回到问题所要求的具体程度。例如一个漏洞的防护问题，只写“加强安全措施”无法构成有用示范；应当说明与该漏洞相关的具体条件和防护内容，同时保持在可靠材料支持的范围内。这个审核过程需要领域判断，所以案例建议请熟悉 Web 安全的人参与，最终保留了 2876 条数据。这个数量是该次筛选后的结果，不代表所有领域都应该准备同样多的样本。

最后将数据导出，登记到 LLaMA Factory 的 dataset_info.json，或者使用 Easy Dataset 生成的对应配置目录。在界面选中数据集后，通过预览检查能否正确读入、问题和回答是否对应。预览成功说明加载与格式配置基本可用；训练后是否更适合业务问题，还要通过与训练数据分开的测试来判断。

总结提炼

高质量微调数据，要同时满足“内容可靠”和“教的工作正确”。一份材料可以属于同一领域，却没有展示模型将来需要完成的任务；一条问答可以单独看完全正确，放进整批数据后却因分布失衡而产生问题。准备数据时，需要在单条样本和整体组成之间来回检查。

这个案例的主线是：用专业资料建立知识基础，用教师模型补充覆盖，再通过不同表达与受众增强多样性，最终由人工检查问题和答案。工具加快了生成过程，训练目标、材料边界和审核判断仍然决定哪些内容值得让模型学习。
