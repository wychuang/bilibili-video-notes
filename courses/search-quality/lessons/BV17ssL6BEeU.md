# Graphify：把散落文件中的概念连起来

> 来源：网络宝藏社｜时长 1分23秒｜阅读强度：快览  
> [Graphify：把代码、PDF、截图整理为知识图谱](https://www.bilibili.com/video/BV17ssL6BEeU/)

一个文件夹里同时放着论文、代码、截图和笔记，文件名还能帮助我们找到某个文件，却未必能回答另一个问题：这些材料之间有什么联系？论文里谈的概念，是否也出现在实现代码和自己的笔记中？文件越多，逐个打开、读完再回忆关联就越费力。Graphify 的用途就是把材料里的概念和关系保存成知识图谱，帮助我们进入这些联系。[00:00:00]

可以把知识图谱先想成一张能查找的关系图：某个概念占一个节点，两个概念之间的联系用连线表示。节点和连线本身不替代原来的论文或代码，它们帮助我们先发现该去哪里看。Graphify 作为供 Claude Code 使用的技能进入文件夹，读取代码、PDF、文档以及图片内容，再提取概念、分析关系。图片和图表需要视觉理解参与，纯文本读取无法直接说明图里画了什么。[00:00:33]

## 同一批关系，可以怎样阅读

最直观的产物是一张交互网页。我们可以点击节点、搜索概念，也可以按主题筛选。假如资料已经积累很多，这些操作让我们先缩小到正在关心的一块，再继续读具体材料。另一类输出是 Obsidian 知识库和百科式文章：前者适合继续放进已有笔记环境，后者把关系转成可连贯阅读的文字。[00:00:48]

除了图，还有一份围绕核心节点、意外联系和使用方向展开的报告。这里的“核心”首先是图中连接较多、值得进一步查看的位置；看到某个节点很显眼，还需要回到它所连接的内容，理解这些联系是否确实对当前问题有帮助。图的结构可以引导注意，但不自动决定某个观点的正确性。[00:01:00]

[[FRAME:00:01:01|报告把核心节点、意外关联和可回答的问题分开，帮助从一张关系图走到具体阅读方向。]]

还有一个与可信程度相关的设计：关系应该保留说明，让读者能区分材料中可直接找到的联系与进一步的推测。看到连线时，值得继续问“这条关系根据什么成立”。把一张图画得复杂，和把每条关系说明白，分别解决了不同的问题。[00:01:06]

这份介绍还提出，建好的图谱能够跨会话保存，后续查询可以少读一些原始文件。理解这个说法时，要把初次整理与之后查询分开：前面先花力气读取、提取，后面才可能复用已经保存的结果。具体节省多少，取决于资料规模、提问方式和实际实现；这段短介绍没有给出可比较的测试条件，因此不能从标题直接得出固定的节省倍数。[00:01:13]

## 总结提炼

Graphify 的用途是先把多种文件中的概念与关系组织起来，再通过图、笔记或文章帮助检索和阅读。真正值得关注的部分是关系能否追溯、内容能否持续复用，以及整理出的结构是否有助于回答自己的问题。
