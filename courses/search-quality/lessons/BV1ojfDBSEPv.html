遇到新名词，先问它替谁做了哪一步

原视频：【闪客】一口气拆穿 Skill / MCP / RAG / Agent / OpenClaw 底层逻辑 · 飞天闪客 · 约 15 分钟。概念入门；行业预测单独看待。

一句话抓住核心

把模型、上下文、运行程序与外部工具拆开，许多看似神秘的 AI 名词就能回到具体职责。

时间戳导航

  • [00:01:00] 用“一次输入，一次输出”理解模型接口。
  • [00:01:52] 对话历史被重新放入上下文，形成连续对话的体验。
  • [00:02:38] 把人工查资料的动作交给程序。
  • [00:04:23] 用结构化格式描述工具调用。
  • [00:05:01] 工具从主程序拆出后，需要通信约定。
  • [00:06:39] PDF 提取、翻译、保存的例子。
  • [00:07:43] 操作说明与脚本组成可复用技能。
  • [00:12:30] 将确定步骤交给程序，模糊判断交给模型。

先记一张地图

名词 我先问什么
LLM 它能根据这次输入生成什么输出？
上下文 这次回答实际看到了哪些材料？
记忆 哪些信息被保存，又怎样进入下一次输入？
RAG 外部信息如何被找回并用于回答？
工具调用 模型提出的操作如何被程序验证和执行？
MCP 应用与外部能力怎样按协议交换请求和结果？
工作流／Skill／Agent 步骤由谁决定，哪些固定，哪些允许运行时调整？

“你刚才说过”不意味着模型自动拥有全部历史。应用可以重放消息、检索记忆或提供摘要；压缩、遗漏和错误检索都会影响下一次回答。这就是为什么评价回答时还要看实际上下文。

用翻译 PDF 的例子理解控制权

[00:06:39] 一个任务包含提取文本、翻译、保存 Markdown。提取与保存已经有稳定脚本时，每次让模型重新发明操作步骤，可能增加成本和失败点。

[00:07:17] 如果输入还包含 Word、PPT，输出也可能变化，可以明确支持的格式和脚本，让运行程序或模型选择合适分支。这里需要权衡可预测性与灵活性。

Skill 可以保存操作说明、质量要求与相关资源；工作流可以固定已知步骤；Agent 可以根据运行结果调整后续动作。同一个产品可以组合这些方法。

哪些简化要留意

原视频用强烈的比喻帮助理解。它把 RAG 主要画成向量检索，把记忆主要画成对话历史，把 Agent 主要画成中间程序；这些都是入门切面，未覆盖完整的架构选择。

Function calling 与 MCP 处在不同的交互边界，二者可以配合。把 MCP 服务改写成脚本能够满足某些本地需求，却不会自然保留远程互操作、能力发现和权限管理等全部特性。

关于 Skill 会淘汰哪些产品、token 会接近免费等内容，属于原视频的未来判断。学习时保留背后的用户需求——减少配置负担——不必把预测当作已经发生的事实。

下一步

迁移练习：画一个“问今天是否适合出行”的流程。标出天气数据从哪里来、谁执行查询、谁解释结果、哪些操作要用户确认。

再问三个问题：找不到数据会怎样？工具返回过期结果会怎样？模型说“已经订票”时，我该检查什么执行证据？这比记住一排缩写更接近真正掌握。
