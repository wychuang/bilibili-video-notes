极简 Agent：少几个内置功能，会得到什么

来源：肖恩君Sean · Pi Agent 极简 Harness 系统设计 · 23 分钟 · 快读。功能与目录按录制版本理解。

一句话抓住核心

把执行循环做小，把可变能力放到扩展里，可以降低理解与组合成本；安全责任仍要有人承担。

先看一个宝可梦查询

视频让外层助手把编码任务交给 Pi，生成一个查询宝可梦资料的脚本。外层负责委派，Pi 负责具体编码，再把结果交回。这个例子说明，编码 Agent 可以作为另一个系统中的一个能力被调用。[00:01:25]

Pi 的几个入口服务于不同使用方式：终端交互适合人直接操作；单次命令适合脚本调用；结构化事件输出方便其他程序观察过程。事件输出能展示可见执行信息，不能据此断言已经获得模型全部内部推理。[00:02:42]

最小工具箱仍然很有力量

读取、写入、编辑和 shell 命令，构成演示中的核心工具。模型据上下文决定是否调用工具，执行结果再回到循环。[00:08:00]

工具数量少，不等于权限小。shell 可以启动其他程序、读取文件和联网；缺少内置审批弹窗时，宿主系统尤其需要限制目录、网络与凭据范围。演示中的简洁体验不应直接复制成对真实电脑的无限授权。

会话树能回到过去，但不会替文件回滚

演示从先前某条对话分叉，继续追问另一只宝可梦。会话树有助于比较不同思路，也便于恢复讨论上下文。[00:10:25]

需要分清：对话分叉与文件版本管理是两个机制。回到旧消息不代表已经撤销磁盘上的修改。做实际编码试验时，仍要保存工作区版本或使用隔离副本。

Skill 和扩展，分别解决什么

视频先写一个查询图鉴的 Skill，说明要获取哪些属性以及怎样操作；再用 TypeScript 扩展定义属性克制计算工具。询问如何击败某只宝可梦时，系统可以调用明确的计算逻辑。[00:14:38] [00:16:50]

Skill 更接近可复用的操作说明，扩展可以注册执行能力与程序逻辑。两者还能打包分发。这样，基础运行时不必预装每个人都未必需要的功能。

代价是组合与维护工作转移到了使用者：包是否可信、接口能否兼容、升级是否破坏原有任务，都需要验证。下载热度不能替代检查。

迁移练习：删掉一个功能再判断

为一个简单文档整理 Agent 列出所有能力，圈出完成任务必需的三个。把其他能力暂时关闭，在相同样本上比较成功率、操作步骤与错误类型。

如果关闭某项能力没有损失，就获得了简化依据；若质量下降，记录具体缺失了什么。用任务证据决定复杂度，比凭“极简”或“全能”的口号更容易做出稳妥选择。
