# 让 Agent 的长期记忆能够纠错

> **来源**：Agent智能体深度研究院，《[Agent记忆] Anthropic公开Claude记忆架构：用Dreaming回查记录，修正笔记并整理知识页》，12:10，https://www.bilibili.com/video/BV1KoW16NEBf/  
> **阅读强度**：standard

Agent 在一次任务里写下的经验，可能从一开始就判断错了；就算当时正确，环境变化后也可能过时。后来的任务若直接照抄旧笔记，错误就会一轮轮传下去。因此，记忆系统需要保存可回查的证据、改正旧笔记，并控制维护成本。

这套设计把任务进行时的记录和任务结束后的整理分开。Agent 做事时可以把认为有用的内容写进记忆；之后再用后台计算回看原始记录、修正判断、整理相关知识页。这种后台整理称为 Dreaming。整理好的少量线索会进入下一次会话的入口，需要细节时再沿着线索找回笔记或完整记录。任务中写笔记会占用当下的注意力，事后回查也要消耗计算资源，所以记忆能否带来收益，要把两部分开销一起算。[00:00:35]

## 四层材料，各自解决不同的查找问题

可以把记忆材料想成由底到顶的四层。最底层保存可搜索的完整任务记录，方便确认当时究竟发生了什么；上一层是 Agent 从经历中写下的记忆笔记；再上一层是按主题组织、彼此链接的知识页；最上层则是新会话自动载入的一小段索引，告诉 Agent 有哪些主题、细节存在哪里。上层材料更容易快速调用，下层材料更适合核实细节。Dreaming 可以在层与层之间来回整理：发现笔记和旧记录冲突时，回到记录检查并改写；发现几页内容相关时，补上链接或合并重复部分；若顶层索引太长，就把细节移回较低层，只留下查找入口。[00:02:04]

记忆要在新会话里发挥作用，还得看它能不能改善后续任务。一组数据库问答实验里，每道题都从新会话开始，只有持久保留的记忆目录能带过往经验；答题反馈也会进入后续记忆。按报告的平均奖励，使用记忆的设置从 0.564 升到 0.828。这个结果对应那组题目和实验设置，说明记忆有机会帮助后续回答，不能单凭一个数字推断它在所有任务上都会提升。[00:03:07]

不同模型留下的笔记质量也会影响记忆能否复用。较弱的记录会猜测答错原因，却没有验证；质量较好的记录会把确认过的事实、支持事实的依据和容易踩的坑分开写。另一组宝可梦游戏运行显示，记下太多并不等于学得更多：一个运行在约一万步时写了 413 个文件、拿到一枚徽章；另一运行只写了 10 个文件、拿到四枚。前一种运行还连续花了 17 步修改记忆，没有推进游戏。若规定模型“只记失败”，收益同样可能下降，因为经过验证的成功做法也会帮助下一题。关键在于记录有用经验，并让未来的任务能读到和验证它。[00:04:20]

## 从月见山的错误笔记到可维护的知识页

月见山的例子把“回查原始记录”说得很具体。角色要穿过山洞，入口附近有一家宝可梦中心。Agent 把宝可梦中心的位置记反，以为它位于山的另一侧，于是从宝可梦中心出来就判断自己已经穿过山洞，还把“月见山已完成”写进笔记。之后的会话继续相信这条记录，角色反复走错路线；原始记忆那组曾三次返回原处。[00:05:28]

Dreaming 重新读取产生错误笔记时的任务记录，对照当时观察到的位置，发现宝可梦中心记反了，再改写笔记。恢复任务后，Agent 从入口重新穿过山洞，到达下一座城市；没有记忆和保留错误记忆的两组都没有到那里。这个例子说明，保存原始观察能给后续纠错提供依据。只有一条总结结论而没有可回看的记录，出了错就很难知道是事实变了，还是当时的判断本来就错了。

当资料很多时，按主题整理的知识页可以减少重复翻找。一组企业文档实验使用约 35 万份内部文件、约 4.2 亿 token，由模型在 128 个会话里持续阅读、创建页面、合并重复页面，并把页面说法与来源对照。在 25 道企业文档问题中，知识页配合搜索的结果最好；单独搜索的达标比例为 53%，组合使用时每题还少用约两万个 token。知识页先帮助找到主题和文档间的联系，搜索再补具体证据；只依赖知识页的最高得分低于两者配合。[00:06:33]

这种整理也有适用范围。并购分析需要把多份文档的信息连起来，知识页帮助较明显；若法律问题的答案直接写在单篇文档里，搜索本身已经够用，整理页面没有明显优势。还有一项任务的知识页体量达到原始文档的 1.77 倍，说明如果页面只是复述材料，就会多出一份要检索和维护的内容。知识页应提供主题关系和查找线索，具体判断仍要回到原文核对。

自动载入的顶层索引也要保持短小。Claude Code 的自动记忆会载入 `MEMORY.md` 开头部分，限制在前 200 行或 25 KB，让新会话先知道有哪些主题、详细内容在哪里。载入太多材料会占用每次会话的上下文；错误若被放在入口，还会被反复带入后续任务。顶层适合放可靠的导航提示，事实细节和证据留在可以继续查找的页面或原始记录里。[00:08:09]

合同分析的例子则说明，某些任务不能为了简短而丢掉细节。多个 Agent 一起把合同内容写进一张条款表时，出现覆盖，也把部分条款概括得不够准确：57 项关键事实最后只保留 41 项。改成每份合同各有独立页面、每页由一个 Agent 负责，并要求逐字保留条款后，重新构建保住了 57 项事实，也满足了简报的评分条件。这里需要明确告诉模型哪些信息不能丢、由谁负责写入；其他知识仍可以由模型自行组织。

整理工作还会继续修复知识页之间的连接。一项法律任务里，九条链接都指向尚未创建的页面，但相关信息已经在另一个页面里。之后的 Dreaming 把链接改到现有页面，并新增了三个页面。持续维护就包括修正失效链接、补充入口和清理重复内容，页面建成后仍要检查它们能不能把读者带到正确材料。[00:09:54]

## 总结提炼

这套记忆设计把原始记录、任务笔记、主题知识页和短索引连在一起。任务中先记录可能复用的经验，后台整理时回到原始记录核实，修正旧笔记并维护页面，再把少量可靠的导航信息交给新会话。月见山的错误位置说明了回查证据如何改变后续行动；企业文档与合同实验则展示了知识页的收益和维护代价。衡量记忆是否有效，应看它能否帮助新任务、能否纠正旧错误，以及节省的检索成本能否覆盖记录和整理开销。
