# Agent 的能力，长在整套基础设施上

> 来源：[秋芝2046 · Agent Infra 到底是什么](https://www.bilibili.com/video/BV1Rz4iz1Exz/) · 23 分钟 · 快读。含云产品介绍与未来展望，本文提炼结构，不作购买建议。

## 一句话抓住核心

Agent 的实际效果由模型、调度、记忆、工具、运维治理和协作共同决定；先找出薄弱环节，再谈升级模型。

## “想拥抱朋友”与“完成拥抱”隔着许多工作

视频用机场遇到朋友的例子：识别并产生行动意图是一部分，协调身体、利用记忆、完成动作又是另一部分。这个比喻用来说明，模型输出行动意图后，系统还要把它接到真实执行中。[00:02:15]

对数字 Agent 也一样。说“我会搜索资料”不等于已经搜索；说“报告已保存”不等于文件确实存在且能打开。

## 用六个问题检查基础设施

| 视频中的层次 | 我会追问什么 |
| --- | --- |
| 模型 | 它能理解约束并选对下一步吗？ |
| 调度 | 步骤如何衔接，失败怎样重试？ |
| 记忆 | 当前信息从哪来，过期内容怎样更新？ |
| 工具 | 能采取什么行动，结果是否可验证？ |
| 运维与治理 | 成本、权限、异常和审计怎样管理？ |
| 协作 | 多个执行者怎样共享目标并合并结果？ |

这是作者便于理解的分层法，并非唯一行业标准。[00:00:58]

## 记忆要区分存在哪里、怎样拿出来

视频区分参数中的知识、当前对话、任务中间状态、长期偏好以及外部资料库。[00:05:50]

关键区别是更新方式。外部记忆可以修改或删除；参数中的知识通常需要训练等机制改变；会话历史则要由系统选择、压缩或取回，再交给模型。

有些系统会发送完整历史，有些只发送摘要和片段。不要把某一种演示机制当作所有产品的实现。保存了信息，也不代表当前任务一定能正确检索出来。

## 工作环境会影响用户体验

Agent 使用本机桌面时，可能占用鼠标和窗口，还会接触私人文件。独立工作环境可以减少这些干扰，提供专用浏览器、代码运行区和持久化文件。[00:11:50]

但本地与云端各有风险：本地要控制文件和凭据访问，云端要关注传输、服务方权限、保存期限和费用。环境位置本身不能决定谁更安全。

视频关于系统自动进化、无限算力、软件入口全面变化的部分属于产品叙事或预测。一次工具反馈是否用于训练、怎样改变后续行为，必须看具体实现，不能默认所有 Agent 都会越用越聪明。[00:13:40] [00:21:15]

## 迁移练习：把“它不聪明”改写成可检查的问题

找一段失败输出，按六层各提出一个可能原因，然后只验证最有证据的一项。例如找不到生成文件，先看保存工具是否成功、路径是否正确，再考虑模型能力。

练习结束时写出一句具体结论：“调用成功，但界面给了错误下载链接。”这样的定位才有明确的负责人和修复入口。
