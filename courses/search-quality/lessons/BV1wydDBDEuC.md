# AI 出了问题，先找到它在哪一层

> 来源：[御豪同学 · AI 核心概念从头梳理](https://www.bilibili.com/video/BV1wydDBDEuC/) · 48 分钟 · 标准学习稿。用视频的三层框架串联概念，并补充容易混淆的边界。

## 一句话抓住核心

用“模型—工程—应用”三层看 AI：模型生成下一步内容，工程连接资料与行动，应用承接用户任务。

## 从一次云南旅行咨询开始

我在聊天框里说“想去云南玩几天”。界面很简单，后面却可能发生很多事：理解日期与偏好，查天气，查路线，阅读攻略，再整理行程。[00:02:24]

天气过期、路线不合理、回答太长，可能来自不同环节。模型可能理解错了“下周”，工具可能用了旧缓存，产品可能没让用户确认出发地。直接贴一个“模型不行”的标签，会错过真正能改的地方。

这就是三层框架的价值：

| 层次 | 主要职责 | 观察问题的入口 |
| --- | --- | --- |
| 模型 | 根据输入生成文本或工具调用等输出 | 给定这些信息，能否理解并推断？ |
| 工程 | 组织上下文、执行工具、保存状态、校验结果 | 信息送对了吗？动作执行了吗？ |
| 应用 | 让用户提出需求、确认选择、使用结果 | 用户要做什么？结果能用吗？ |

这是教学用的视角，实际系统的边界可以交叉；同一个 Agent 既有工程实现，也有面向用户的交互。

## 模型：接着已有内容，预测下一段

视频用“这期视频很……”演示下一个 token 的概率分布。一次次生成并接回上下文，最终组成完整回答。[00:07:50]

可以写成：

\[
P(y_t\mid x,y_{<t};\theta)
\]

这里 \(x\) 是输入，\(y_{<t}\) 是已经生成的内容，\(\theta\) 是模型参数。token 是模型处理的文本单位，可能是一个字、一个词的一部分或其他片段，不能固定等同于一个汉字。

输出时还要从分布中选择 token。采样策略会影响多样性，因此同样的问题可能得到不同回答。温度降低可以减少一些随机性，但不等于事实正确，也不保证整个应用每次完全一致。[00:11:55]

输入也不只有用户那一句话，还可能包括系统规则、历史对话、工具说明、检索资料。上下文窗口限制的是模型一次能处理的范围；资料“曾经出现在对话里”，不代表本轮仍被完整送入。

## 工程：把模型接到真实世界

推理运行环境负责实际执行模型。提示词则描述任务、相关信息与输出要求。视频的涨跌判断例子很直白：给昨天和今天的指标，要求输出“上涨”或“下跌”。如果两天相等，规则还要补上“持平”，否则输出格式本身就在制造错误。[00:13:15] [00:18:20]

少量示例可以帮助说明期望。复杂任务也可以拆步。但写上“三位专家一起讨论”只是一种提示方式，不能自动获得三个独立专家的真实核验。

另一个边界：不同消息角色、工具结果和不可信文档应有明确区分。它们最终都进入模型处理，不意味着系统可以忽略指令层级，把文档里的命令当作用户授权。

## Workflow 与 Agent：谁决定下一步

天气提醒有固定步骤：取数据、判断、展示。可以把这些步骤写成工作流，只把需要语言理解的部分交给模型。[00:21:10]

当下一步取决于刚查到的情况，就可能需要 Agent 循环：观察结果，决定行动，执行工具，再观察。真实产品常把固定流程和动态决策结合使用。[00:23:12]

因此自治程度应随任务变化。发送邮件、提交订单、修改数据库等有外部影响的动作，需要权限和确认边界。能够自行选择工具，不代表可以自行扩大任务范围。

## MCP、RAG、Skill，各自补哪块能力

**MCP 处理连接约定。** 服务端暴露能力，客户端按约定连接。它不仅是工具说明的写法；规范还涉及消息交互等内容。接入成功后，权限、参数验证和正确使用仍要由系统落实。[00:29:00]

**RAG 处理外部证据的获取与使用。** 长文档通常需要解析、索引和检索，选出与问题相关的部分再用于生成。RAG 可以通过 MCP 暴露成工具，两者能够组合。向量数据库是一种实现选择，并非所有 RAG 都必须有它。[00:33:02]

**Skill 保存可复用的做事方法。** 例如创建表格时用什么步骤、模板与检查方式。它帮助 Agent 重用经验，但通常不会直接改变模型参数；写了步骤也不等于步骤已被执行。[00:36:37]

记忆又是另一个维度：要决定保存什么、何时读回、怎样更新和删除。外部文档库可以成为信息来源，但不应把所有记忆都简化成一个向量库。

## 上下文与运行框架：信息给对，也要做对

上下文工程关心当前任务需要哪些信息、怎样压缩与排序、哪些旧内容可以移出。资料越多，噪声和费用也可能越高。[00:40:18]

运行框架（harness）还要管理执行循环、工具、权限、状态、失败恢复与观测。视频后段强调验证和反馈：生成了代码，就运行相应测试；生成了文件，就检查文件是否存在且能打开。[00:43:31]

这些工程词的使用范围并不总是统一。学习时抓住职责即可，无需把每个新词理解为一种彻底独立的技术。

## 迁移练习：给一次失败画出最短链路

选一个 AI 回答，按“用户输入 → 实际上下文 → 工具或检索 → 候选答案 → 用户行动”写五行。标出第一个有证据支持的异常，暂时保留其他猜测。

例如原回答推荐了已停业的店：先检查检索时间、来源和营业信息，再判断模型是否忽略证据。练习的目标是把批评落到一个可验证、可修改的环节。
