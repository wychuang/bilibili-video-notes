想让 AI 帮忙制作一个每天整理录音的工具，可以怎样交代？这段口述从已有项目出发，逐步说明录音来源、处理链、输出、安装体验、定时任务与验证。它呈现的是一份任务要求，视频没有展示完整实现与最终验收。[00:00:33]

## 先说清输入、处理和输出

案例希望每天处理来自 Voice Memos 的录音：先同步音频，再运行语音识别（ASR）得到 CSV，随后调用 Codex 命令行处理转写。第一版暂不要求识别每位说话人的身份。[00:00:53]

想要两类结果：一个格式化 HTML，包含当天发生的事和待办事项；另一个放在 `meetings` 文件夹，保存会议相关输出。HTML 可以由 Markdown 生成。明确这些中间文件与最终产物后，执行者才知道每一步应该接收什么、交付什么。[00:01:39]

原有流程中已有提示词，要求将中文翻译为英文时保留原意和细节。这里有一个实用的交接问题：经过多轮修订的提示词可能包含具体限制，改写前先理解其用途，避免把重要条件一并删去。[00:02:02]

## 让新用户能安装，也能验证

计划把流程整理成可分享的 skill，并编写 README 介绍安装。安装时引导配置 Python、语音识别及命令行工具，再用一段很短的示例音频跑通处理链。这样使用者可以先确认环境和输出路径，再处理自己的录音。[00:02:28]

定时方案设想每天午夜由 cron 调用 Python 脚本。口述特别提出：修改已有定时任务前先备份，采用追加方式，避免删除用户原有安排；还要提醒用户运行条件，包括电脑保持运行和所需录音应用状态。[00:03:26]

录音、转写和会议记录可能包含个人或他人的敏感信息。实际实施前需要确认录音及处理的授权、存储位置和外部服务的数据处理方式。脚本是否能如期运行，也要按实际系统的睡眠、权限和网络条件检查。

## 把工作拆成可检查的步骤

口述最后列出顺序：先调研；建立项目并写需求和设计文档；实现命令行和测试；生成约十秒的示例音频并跑初始验证；完成 README；检查隐私和安全；最后准备仓库并发布。每一步都有可以查看的结果，便于发现遗漏。[00:04:25]

发布到公开仓库前，尤其要检查示例音频、转写、配置和日志是否包含真实私人信息。这里的发布只是案例中的计划；视频未展示这些步骤已完成，也没有展示定时任务实际执行。[00:05:22]

## 总结提炼

这份提示词有清晰的数据路径：录音同步 → 语音识别 → CSV → 内容处理 → 日报与会议文件。它还补充了首次安装、样本验证、保留既有定时任务和发布检查，使需求更容易交给执行者。
