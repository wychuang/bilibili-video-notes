# 找到“长得像”的句子，为什么仍然答错？

> 原视频：Embedding 正在摧毁你的 RAG？？ · 果粒奶优有果粒 · 约 26 分钟。本文保留案例，并单独检查其中推论的边界。

## 一句话抓住核心

**向量距离可以帮我缩小搜索范围，但距离近的材料，未必包含当前问题需要的那条事实。**

## 推理主干

问题要求特定事实 → 检索器按某种相似性排序 → 相近概念混入 → 生成模型拿着偏掉的证据回答 → 我需要回到业务里的“相关”究竟指什么。

想象我要查某位国王的母亲。找到一篇同名国王的传记，看上去比找到一张陌生的家谱更“相关”；但真正能回答问题的，可能恰好是家谱里的那一行。这个区别决定了检索系统能否交付正确答案。

## 1. “像”至少有几种不同意思

[00:00:28] embedding 把文本编码成数值向量。它的用途是让计算机可以比较文本之间的关系；它不会自动替我定义业务问题里的正确答案。

[00:03:47] 原视频用 king、queen、ruler 做对照：国王与王后在语境中经常一起出现，都属于皇室角色，所以它们可能获得较高的相似度。可是当任务要求找一个可以指代国王的词时，ruler 这种“统治者”的表达可能更有用。

[[FRAME:00:04:00|画面并排展示 king 与 queen、ruler 的分数及完整句子的比较；这些数字属于这次示例。]]

这里容易混淆两件事：共同出现、属于同一话题，能够产生相近的表示；满足特定问题的条件，还需要检查身份、关系和限定词。原视频口述及自动字幕里的个别英文释义不准确，ruler 在这个语境下应理解为“统治者”。

[00:06:17] 之后的例子把问题拆成四类：对象是什么、发生在何时、位于何处、采取什么动作。猫与狗都属于常见宠物，但猫的属性问题可能更需要猫科动物的资料；两个数字外形接近的年份，也可能指向完全不同的时期。

我应当问的具体问题是：**当前检索器是否保住了任务真正敏感的差异？** 对维修手册来说，这可能是零件型号；对政策问答来说，是适用地区和生效日期；对人物查询来说，是同名消歧。后面这些属于迁移例子。

## 2. 相似度高，仍然可能找错人

[00:09:47] 原视频引用了一个阿方索二世与阿方索七世的回答混淆案例，并比较名字和关系词变化后的相似度。

这个案例值得记住的部分是：问题中的实体身份很关键。把“谁的母亲”里的“谁”弄错，剩下的语言再流畅也无法补救。

但仅凭输出错误，无法反推出模型训练集中究竟包含了谁、遗漏了谁。原视频对训练语料的解释属于推测，没有展示可以验证内部训练数据的证据。公开学习笔记应把“观察到混淆”与“已经知道内部原因”分开。

同样，某两个短语的向量得分，也不能直接当作事实正确率。要评价检索器，需要准备真实问题、相关文档标注，并统计它在整组任务上的表现。

## 3. 加上重排、图谱，问题会自动消失吗？

[00:13:03] 后半段依次讨论重排、知识图谱、混合检索和长上下文。可迁移的问题意识是：多加一个组件，需要检查它是否真的修复了当前错误。

[00:16:32] 原视频引用不同研究的分数，表达对一些方案表现的怀疑。这里必须保留一个边界：不同论文的任务、数据集、模型和指标未必可比。某项测试得分较低，无法独立证明重排或图谱整体无效。

[00:20:17] 复杂组合还会带来延迟。我的优化目标至少有两项：用户拿到的答案是否更可靠，以及等待和资源成本是否值得。堆叠组件如果没有消融实验，就很难知道改善来自哪里。

[00:21:00] 长上下文可以让模型读更多内容，但“放得进去”与“能稳定找对并利用”是两个需要分别测试的能力。读入更多材料，也会增加无关信息和冲突证据的处理负担。

## 4. 回到数据，先把关系分清楚

[00:22:43] 最后的建议是先结合业务缩小范围，再做向量匹配。[00:23:01] 用到的关系包括同义、上下位、整体与部分。

[[FRAME:00:23:20|关系表列出同义、上下位、整体与部分，提醒我先确定任务所需的语义关系。]]

这些关系对应不同的检索需求：

| 关系 | 直观例子 | 要检查什么 |
| --- | --- | --- |
| 同义或别名 | 剃须刀、刮胡刀 | 换一种说法，能否找到同一对象 |
| 上下位 | 动物与狗 | 广义知识是否适用于具体对象 |
| 整体与部分 | 汽车与方向盘 | 问部件时，能否定位到相关章节 |
| 身份与条件 | 人名、型号、日期 | 看似相近的对象是否被混为一谈 |

[00:24:37] 维修手册的例子提醒我：最值得构造的评测样本，往往就在实际业务的常见说法和容易混淆的对象里。
